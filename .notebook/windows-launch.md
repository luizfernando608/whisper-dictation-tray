## Histórico anterior

`main.py:main()` sem argumentos inicia apenas a bandeja; se a mesma instalação já estiver aberta, sai sem abrir janela. Atalhos interativos precisam de `--recordings` ou `--settings`. `installer.iss:[Icons]` e `[Run]` usam `--recordings` nos atalhos principais e na abertura após instalar; `[Icons]` mantém a inicialização automática sem argumentos.

O canal IPC é único entre instalações. Uma instalação antiga iniciada pelo Windows impede a prévia de assumir os atalhos globais; a prévia detecta o conflito e pede para fechar a antiga. No computador de desenvolvimento, atalhos de menu Iniciar/configurações/gravações e inicialização foram alinhados à prévia existente em 2026-10-20, com cópia dos atalhos anteriores em dados locais de backup. A versão instalada antiga foi encerrada via IPC e a biblioteca da prévia foi aberta pelo atalho principal para verificar o resultado. Configuração e gravações não foram migradas.

O helper de atualização salva binários e integração Windows antes de instalar. `update_integration.py` preserva a chave HKCU `Pace_is1`, atalhos conhecidos em pastas do Windows e os desinstaladores. Em falha, restaura também essa integração: os atalhos novos com `--recordings` não funcionam no CLI 1.4.0. Se os binários forem recuperados, tenta reiniciar a versão anterior mesmo que algum recurso de integração falhe; mantém erro e backup para diagnóstico.

`installer.iss` exclui somente fixtures `onnx/backend/test` e cabeçalhos `torch/include`: caminhos longos desses arquivos interrompiam uma instalação real, e os dois diretórios não são necessários para os runtimes empacotados. Os ensaios reais de instalação, atualização, recuperação e captura estão documentados em `.specs/features/meeting-recordings/install-validation-2026-10-20.md`. Scripts `validate_windows_installation.py`, `validate_installed_pipeline.py` e `validate_installed_capture.py` são manuais e opt-in; não rodar automaticamente com a suíte.

`updater.check_for_update()` consulta somente `/releases/latest`: o instalador local não fica disponível pelo botão antes de um release estável público. Publicar exatamente `Pace_Installer.exe`, com digest SHA-256 e tamanho fornecidos pelo GitHub; draft/prerelease não libera o fluxo. O cliente 1.4 abre o instalador pelo fluxo antigo; o novo helper de reinício só vale depois de receber 1.5. Uma prévia já marcada como 1.5 não oferece reinstalar outro build 1.5. A compatibilidade do parser/download antigo e o botão Tk novo foram inicialmente verificados com transporte de release simulado.
